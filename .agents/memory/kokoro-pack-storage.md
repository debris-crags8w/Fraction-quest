---
name: Kokoro pack storage
description: Where pre-generated voice audio lives and how every pull request keeps it complete.
---

Heart (`af_heart`) is the learner-facing lesson voice. The story cast uses separate Kokoro voices for scripted character lines; these are not general voice settings. Michael and Emma remain retired app-level choices, with saved values falling back to Heart. Heart and cast audio live in App Storage; each sentence has an Opus `.caf` and an MP3. Keep the generated index and audio out of Git.

**Why:** The user chose one voice for read-aloud across lessons; the story-cast voices serve narrative dialogue only. Bulk backfills include Heart plus the configured cast voices.

The Voice pack workflow sends the current sentence manifest to the authenticated Replit API. Replit compares it with App Storage, renders small PR gaps with Kokoro, writes directly to storage, and verifies the result; GitHub does not render or upload the audio. The check should be required. Keep automatic PR sync bounded so a forgotten full-pack backfill cannot unexpectedly launch thousands of renders; use the Replit batch command for a large gap. Previously merged MP3 blobs remain in Git history unless a history rewrite is explicitly approved.

**Why:** The pack is thousands of files and tens of megabytes, which bloats source and deployments. The Replit app server can write directly to App Storage; GitHub Actions must call its public API rather than access storage itself. A bounded PR check prevents text reaching main without audio while keeping bulk regeneration intentional.

**How to apply:** Set `VOICE_PACK_UPLOAD_TOKEN` (32+ characters) in Replit Secrets for the published API, and the same token plus the published app's base address as GitHub secrets `VOICE_PACK_UPLOAD_TOKEN` and `VOICE_PACK_UPLOAD_URL`; no separate API host is needed because the API is under `/api`. The project uses one Replit Routine for daily maintenance, running `pnpm --filter @workspace/api-server run daily-voice-backfill`; do not enable a duplicate `.replit` schedule or deployment-based scheduler. Avoid overlapping the Routine with a manual bulk backfill. GitHub Actions still needs the published API URL and token. Until the app is published, those secrets stay unset and the PR check passes with a warning instead of failing. The daily job renders at most 100 sentences per run and leaves the rest for the next run, so a large lesson change never needs a manual step. Serve audio with a long immutable cache (files are named by sentence). Never prune before the live app stops using a file.

**Why:** Replit's current App Storage documentation explicitly supports Scheduled Deployments for storage maintenance. Earlier project notes incorrectly stated they could not access App Storage; the schedule uses the same project's SDK credentials and is billed only for its run duration.

A Replit shell backfill can be interrupted while completed App Storage writes persist; a hard timeout can leave its shared lock in place until the two-hour lease expires. Reruns recount the actual missing files and skip existing clips. **Why:** A timed-out batch left a valid-looking lock after its process ended, so immediate retries were blocked even though no writer remained. **How to apply:** On interruption, check for active writers and inspect the lock expiry. Prefer waiting for expiry; if immediate continuation is needed and the lock is confirmed stale, remove only that lock with a generation-conditional delete. Never remove stored audio to resolve a lock issue.

Treat every voice-pack audit count as a snapshot, not a durable deletion list. Rebuild the current sentence manifest and rerun the guarded preflight immediately before pruning; abort if the live manifest differs or any active sentence is missing. **Why:** Lesson text can change between audits and cleanup, so an earlier unreferenced-file count may no longer describe what the app currently needs. **How to apply:** Backfill current missing audio first, then get a fresh audit before considering removal; never delete by reusing a count from an earlier run.
