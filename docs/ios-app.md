# Fraction Quest for iPhone and iPad

*Branch `ios-local-icloud`. Not merged into `main`.*

The iOS app uses the same web app, bundled into a native shell with [Capacitor](https://capacitorjs.com) 8. It has **no accounts**: progress is saved on the device and, when the device is signed in to iCloud, synced through the family's own iCloud. The developer never receives the data, so the App Store privacy label can be **"Data Not Collected"**, as long as no analytics script is added.

## What's in this branch

| Piece | Where | What it does |
|---|---|---|
| Native project | `artifacts/fraction-quest/ios/` (Xcode, Swift Package Manager) | Generated by Capacitor. Bundle id `com.fractionquest.app` (change it, see below) |
| iCloud plugin | `ios/App/App/ICloudSync.swift` | `NSUbiquitousKeyValueStore` (iCloud key-value storage, up to 1 MB). Methods `isAvailable`, `get`, `set`; event `changed` when another device saves. Registered in `AppViewController` |
| iCloud entitlement | `ios/App/App/App.entitlements` | `com.apple.developer.ubiquity-kvstore-identifier` |
| Device storage + sync | `src/lib/native.ts` | Before the app renders, restores every `fraction-quest-*` key from the device's storage (Capacitor Preferences) and merges iCloud (waits at most 2.5 s). While running, it copies every save to device storage and iCloud (debounced, merging iCloud first). When the child returns to the app, it shows other devices' work |
| Child profiles | `src/lib/profiles.ts`, `src/Family.tsx` | Up to 6 children, no passwords. Kids switch from the name chip on the map; grown-ups add, rename or remove children in **For grown-ups** |
| Merge rules | `src/lib/merge.ts` | Never loses progress: each lesson keeps the copy with more evidence; scores keep the best; settings stay as on the device |
| Backup / restore | `src/Family.tsx` (grown-ups page) | One JSON file with every child. On iOS it opens the Share sheet (save to Files, AirDrop, email). Restoring merges and never erases |
| No accounts on iOS | `src/account.tsx`, `src/App.tsx` | The iOS app never shows sign-in. The website keeps its optional accounts, and profiles appear there only when not signed in |

The website works the same as before, plus child profiles and backup/restore for guests.

## Build and run (needs a Mac with Xcode 16 or later)

```sh
pnpm install
cd artifacts/fraction-quest
pnpm run build:ios        # builds the web app and copies it into ios/ (npx cap sync ios)
npx cap open ios          # opens Xcode
```

**One-time setup in Xcode:**
1. **Signing & Capabilities → Team:** pick your Apple Developer team.
2. **Bundle Identifier:** change `com.fractionquest.app` to your own (for example `com.yourname.fractionquest`). Also change `appId` in `capacitor.config.ts` to match, then run `npx cap sync ios`.
3. **+ Capability → iCloud:** tick **Key-value storage**. Xcode reuses `App/App.entitlements`; the identifier `$(TeamIdentifierPrefix)$(CFBundleIdentifier)` is already filled in.
4. Run on a device or simulator. For the iCloud test, sign the simulator or device in to an Apple ID (**Settings → Sign in**).

**After changing web code:** run `pnpm run build:ios` again. It re-copies the build; Xcode doesn't need reopening.

## How it was tested here (no Mac available)
- **Unit tests** (`src/game.test.ts`, "device saving, child profiles and iCloud merge"):
  - profiles swap data correctly
  - merge never loses progress
  - a second device's record merges, and removed children stay removed
  - merging the same copy writes nothing (no save loops)
  - backups merge and reject other files
  - six children with every lesson done fit in 1 MB
- **Simulated iPads:** two browsers loaded Capacitor's real iOS bridge script (`native-bridge.js`) with stand-in device storage and a shared stand-in iCloud. Checked:
  - the app runs as native with no sign-in screen
  - a new iPad gets all progress on first launch
  - work on iPad B reaches iPad A when A returns to the foreground
  - progress survives iOS clearing the web view's storage
  - no repeated iCloud writes
- **Swift and Xcode:** the Swift plugin and Xcode project have **not been compiled**. The project file was checked with a parser (the plugin file is in Sources, entitlements are set for Debug and Release). **First step on a Mac: build it.** If the compiler objects, the plugin is short (`ICloudSync.swift`).

## Still needed before App Store submission
1. **App icon and launch screen:** `ios/App/App/Assets.xcassets` still has Capacitor's defaults. A 1024×1024 icon is required. `npx @capacitor/assets generate` can make every size from one image.
2. **Printing:** the printables call `window.print()`, which does nothing in an iOS web view. Add a native print step (for example, the `@capgo/capacitor-printer` plugin or a small `UIPrintInteractionController` plugin), or share the page as a PDF.
3. **Parental gate on outside links:** the map footer links to Zearn and DreamBox. Kids apps must put a parental gate before any link that leaves the app (guidelines 1.3 / 5.1.4), or remove the links in the iOS build.
4. **Privacy policy page:** required even with no data collected. Say that progress stays on the device and in the family's iCloud, that names are optional nicknames, and that there are no ads, analytics or accounts. Link it in App Store Connect and in the grown-ups page.
5. **App Store Connect:**
   - Kids category with age band (6–8 or 9–11)
   - privacy label "Data Not Collected"
   - screenshots for iPhone 6.9″ and iPad 13″
   - description, support URL, and review notes ("no account needed")
6. **Testing on real devices:** iPhone and iPad (rotation, split view), plus iCloud sync between two devices on the same Apple ID. Also test:
   - offline launch
   - a device without iCloud: progress saves locally, and the grown-ups page says so
7. **Optional:** remove the unused analytics hook (`src/lib/analytics.ts`) from the iOS build to keep the "Data Not Collected" label easy to defend.

## Notes and limits
- **iCloud limit:** iCloud key-value storage allows 1 MB per app; a family of six with every lesson done is well under that (checked by a test). If it's ever full, the grown-ups page says so and suggests a backup.
- **Simultaneous saves:** if two devices save at the same moment, iCloud keeps the later copy. Each save merges iCloud first, and every device re-saves on its next change, so nothing is lost for long.
- **Same Apple ID only:** profiles sync between devices on the same Apple ID (one iCloud). Children on different Apple IDs, such as their own iPads under Family Sharing, don't share data. Use **Save a backup** / **Restore a backup** to move a child between them.

## Subscription (built on this branch)
**The plan:** unit 1 is free. Every part of units 2–14 needs the monthly subscription: **$2.99/month** with a **7-day free trial**. The website stays fully open for testing.

| Piece | Where | What it does |
|---|---|---|
| Access rules | `src/lib/access.ts` | **The one place** that decides what's open: `missionOpen`, `unitOpen`, `levelQuizOpen`, `openProgress` (drops reviews and today's practice from locked units). Constants: `SUBSCRIPTION_PRODUCT_ID` (`com.fractionquest.app.monthly`), `TERMS_URL` (Apple's standard EULA), `PRIVACY_POLICY_URL` (**empty, must be set before submission**) |
| Where it's enforced | `src/App.tsx`, `src/ParentView.tsx` | Map (locked units and lessons show 🔒), lessons, lab, redo, worksheets on paper, extra practice, all four games, unit challenges, daily practice, quick review, level quiz, and grown-up answer keys |
| StoreKit 2 plugin | `ios/App/App/Subscriptions.swift` | `getProduct` (localized price, trial eligibility), `purchase` (handles Ask to Buy "pending"), `getEntitlement`, `restore` (`AppStore.sync`), `manage` (Apple's manage sheet), plus an `entitlementChanged` event from `Transaction.updates`. No third-party SDK |
| Subscription state | `src/lib/subscription.ts` | Keeps the last App Store answer on the device (valid only until its period ends), asks again at launch and when the app returns to the foreground |
| Screens | `src/Paywall.tsx` | Kids see "This part is locked, ask a grown-up." Grown-ups pass the maths gate, then see the offer (price from StoreKit, trial only if eligible), Subscribe / Start free trial, Restore purchases, the renewal terms and the Terms of Use link. **For grown-ups** has a Subscription section (status, Manage subscription, Restore) |
| Website preview | `?paywall=1` | Shows the locks in a browser, with a "Pretend to subscribe (testing)" switch. Never in the iOS app |

**Progress is never lost:** if a subscription ends, everything stays saved and unit 1 stays playable. Units 2–14 lock again until it's renewed.

### App Store Connect setup (once)
1. **Agreements:** sign the Paid Apps agreement and add banking and tax details. Purchases don't work without it, even in testing.
2. **Create the subscription:** in **Subscriptions**, create a subscription group (for example "Fraction Quest"), then an auto-renewable subscription:
   - Product ID: `com.fractionquest.app.monthly` (or your own, and update `SUBSCRIPTION_PRODUCT_ID` to match)
   - Duration: 1 month
   - Price: $2.99 (Apple sets equivalents for other countries)
   - Display name and description, and a review screenshot of the subscription screen
3. **Free trial:** on that subscription, add an **introductory offer**: Free, 1 week, for new subscribers.
4. **Small Business Program:** enroll so Apple's commission is 15%.
5. **Privacy policy:** add the URL in App Information and set `PRIVACY_POLICY_URL` so the link shows on the subscription screen. Apple requires both the Terms of Use and Privacy Policy links in the app for subscriptions.
6. **App Review notes:** "Unit 1 is free. The subscription unlocks units 2–14. Purchase screens are behind a grown-up gate (multiply two numbers)."

### Testing purchases on a Mac
- **Quickest:** in Xcode, choose File › New › File › **StoreKit Configuration File** (synced to App Store Connect, or local). Add the monthly subscription with a 1-week free trial, then pick that file under **Product › Scheme › Edit Scheme › Run › Options › StoreKit Configuration**. Purchases, renewals, expiry, Ask to Buy and refunds can be simulated in Xcode's **Debug › StoreKit › Manage Transactions**.
- **On a real device:** use a **Sandbox** tester (App Store Connect › Users and Access › Sandbox). A sandbox month renews every few minutes, so expiry is easy to test.
- **Check that:**
  - units 2–14 are locked on a fresh install
  - the trial starts and everything unlocks
  - Restore purchases works on a second device with the same Apple ID
  - cancelling, then letting the period end, locks units 2–14 again with progress kept
  - an Ask to Buy request shows "Waiting for approval," and unlocks once approved
